## Why are we still writing assembly ?

This is a good question; actually, why bother when we can just write C and compile it ?  
Well, sometimes we need to handle all the `CPU state` in a really specific way. We don't want any kind of optimization from C to asm, and we want the CPU to do exactly what we want with its `registers`.

Like for example, for a `context switch`, we want to save `all registers` and save them in `memory`. If we write the routine for that in a higher-level language, some kind of `optimization` can be made, and the compiler can use a register to store some value, and then, saving the context, we lose a register by saving a value inside it. So we save some `garbage`, and when the task restores its `CPU state`, it will want to use that register. The task will think that the previous value it saved in that register will be the same, and then `BAM`, no, it's not. It will use the garbage and can lead to a kernel panic or undefined behavior. There are also some instructions that `don't have` an `equivalent` in higher-level language, like `mret` in RISC-V. You want to use `mret` ? You need to write it in assembly.

## What's an ISA ?

ISA means `Instruction Set Architecture`; it’s the `abstraction` between the `CPU hardware` and `software`. It defines the supported instructions, data types, registers, etc.

When we write assembly, we use CPU instructions defined in the CPU architecture ISA. So writing RISC-V and ARM assembly is not the same, because this is 2 different ISAs.

The RISC-V ISA is, I think, easy to read and write, making it really accessible for newcomers to assembly writing.

## How to write assembly ?

If you never, ever wrote assembly, this can be really scary, but you'll see it's pretty straightforward.

When we wrote assembly, we wrote CPU instructions, like:

```asm
# Move value in one register to another register
# mv is actually a pseudo instruction, not a real instruction from the ISA
# Meaning that when we compile our code, the CPU will not execute the instruction mv
# it will execute the instruction `addi`
mv
# Store a word(usize, or 4 bytes on 32 bits system) from one register to a memory address 
sw
# Load a word(usize, or 4 bytes on 32 bits system) from a memory #address to a register
lw 
# Addition a value from two given registers and store it to another register
add
```

So, this is some assembly instruction. Now, we will never write something like that, because we just use the instruction alone; we don't use any registers with them, if we want to write real assembly, we will write something like that:

```asm
# Move the value of a1 into a0
mv a0(destination register), a1(source register)
# Store the value in the source register(a0) into the memory address `MEMORY_ADDRESS`
sw a0(source register), MEMORY_ADDRESS(destination memory address) 
# Load the value from the MEMORY_ADDRESS into the destination register(a0)
lw a0(destination register), MEMORY_ADDRESS(source memory address)
# Add the values of a1 and a2, and save it into a0
add a0(destination register), a1(source register 1), a2(source register 2)
```

Now that's real assembly code snippet !

## Branches

Now that we know how to write some assembly instructions, that's great, but there's a thing that's really important, and we can't do a lot without it. It's like `conditions`; in a higher-level language, without conditions, we are restricted.

Conditions in assembly are branches; we use a special branch instruction with registers and define a branch using labels. Here's an example:

```asm
# Load immediate 0 value into a0 register
li a0, 0
# Branch instruction, bnez -> Branch Not Equal Zero, so it's like writing, if a0 != 0, goto 1f
# Because a0 contain 0, the branch will not be taken, so we will continue execution with next instruction, but if a0 contain a value != 0, the next instructions will go directly to the 1f branch.
bnez a0, 1f
# ... Other instructions
mv t5, s11
add s1, t5, t6
# ... Other instructions

# 1 label, for the branch, using 1f meaning 1 forward, to go to the next label 1, so #we can have multiple `1` label
1:
 # other instructions
```

We use the `bnez` instruction (Branch Not Equal Zero); it's a `pseudo instruction` too; the compiler will translate this to `bne a0, x0, 1f`.

We can also use multiple branches:

```asm
li a0, 1
bnez a0, 1f
# ... Other instructions
1:
 # At the start of the branch, we can check a register to goto another branch
 # beqz -> Branch Equal Zero
 # At the start of the 1 branch, we check if a register is equal to 0, if it is, we go to the label 2 branch forward, so we exit the current branch
 beqz a1, 2f
 # ... instructions that update a1
 # At the end of the branch, we can check a value, and restart the branch 
 # 1b meaning 1 back, so the previous label 1 branch, the one we are into
 bnez a1, 1b
2:
```

So that's how we can use multiple branches. This is very useful, for example, to copy a lot of memory from one place to another.
